# SONIC AI-C — real owner inbox review and provider-receipt differentiation

**Purpose:** reduce missed cleaning-service leads without inventing replies, SLA violations, delivery, permission to send, or AI predictions. The owner-scope server reader `loadAuthorizedOwnerInboxReview` double-reads authenticated operational workspace snapshots; the pure `planOwnerInboxReview` fails closed if either bounded workspace history reaches the read limit (200 conversations, 1,000 messages), records/IDs are inconsistent or timestamps invalid. It inspects last saved customer inbound against explicit delivered/read outbound receipts; queued/provider-accepted/failed is marked DELlVERY_UNVERIFIED, and active handovers require owner review even after delivery. Returns scoped conversation ids, reasons, no message body/contact, no sends or model execution. Complete-history guarantee depends on the existing `loadOperationalStaffSnapshot` bounded workspace query; reaching the limit suppresses all classifications.

**Next product integration:** owner Inbox could show these evidence-backed review links; real positive saved-message owner UAT and provider receipts mandatory. This does NOT call Codex or send automated follow-ups. Future workflow events must be journaled transactionally before unattended delivery.
