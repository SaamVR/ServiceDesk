# R44 AI provider readiness: honest proof gate
Previously `evaluateAiProviderReadiness` elevated three arbitrary caller-provided boolean observation flags into `PROVIDER_VERIFIED`. This cannot establish an actual controlled authenticated provider inference, and can mislead merchant owners into believing AI has been deployed. The readiness checker now requires a separate persisted authenticated provider receipt that its current interface **does not possess**: it reports `CONTRACT_TESTED` at best, with an explicit missing receipt, until an independently authorized server verifier is integrated.

It also accepts only literal boolean `true`, rejecting truthy string/numeric config data. This is a deliberate fail-closed status change, not provider disconnection or an inference test. The earlier separate public Samai synthetic probe stays independently provider-verified as a probe; it does not prove the commercial multi-tenant ServiceDesk AI configuration. No traffic, tenant enrollment, key handling or production deployment changes.
