**Scope:** deterministic in-process integration regression only; not a customer transaction, authenticated owner UAT, real bank or provider receipt, or persistent database acceptance.

## Explicit limitations

There is **no database write or real authenticated session** in this contract. The code does not prove that every step is atomically chained to the same persisted owner, branch or customer in connected staging, nor that invoices or action rows were generated by the real application. Model, provider, customer session and payment networks are not invoked. This is a regression seam for the commercial state machine, not a release authorization for real money or external messages.

For commercial acceptance, require separately approved real owner prices, two distinct owner QA accounts, a persisted request and customer-accepted quote in the same priced branch, a server-side invoice/hold, an authorized controlled payment fixture with committed ledger application, a durable attention item tied to the actual workflow execution, negative cross-tenant RLS, and an owner-signed manual UAT receipt. Current staging intentionally lacks those prerequisites.

Never apply migration 0063 to connected staging, seed arbitrary owner rates, turn on workers, send customer/provider traffic, or promote production main based on this synthetic test.
